# v0.1.0 — Paper Safety Baseline

Release type: `source-only prerelease`

Release date: 2026-07-26 KST

Publication PR: [#31](https://github.com/YoongeonChoi/msp/pull/31)

> [!WARNING]
> This release does not authorize Production Live trading. It contains no signed
> desktop binary, no automatic deployment, and no broker order-write network path.
> `G0`, `G1`, and `G2` remain `FAIL`; Production Live remains `NO-GO`.

## Purpose

`v0.1.0` establishes a reproducible source baseline for the Paper-only Korean stock
trading control system. The release joins the safety-first Worker, Supabase control
plane, Tauri operations cockpit, PIT research data boundaries, Paper V2 accounting,
and the sealed durable operations scheduler under one reviewed history.

All committed version surfaces already declare `0.1.0`. No version rewrite is needed
for this first prerelease.

## Added

- A DB-clock scheduler for exactly five operations jobs: `commands`, `execution`,
  `settlement`, `reconciliation`, and `outbox`.
- Durable job definitions, runs, inner leases, retry budgets, dead letters, and
  reason-bound manual replay evidence.
- Outer Worker lease and inner scheduler lease binding with release SHA, fencing token,
  invocation deadline, stale-writer rejection, and startup command drain.
- A sealed production capability graph that rejects arbitrary registry aliases,
  reconstructed handlers, unmanaged transports, and authority drift.
- Rolling-compatible durable heartbeat evidence consumed by paper health, dead-man,
  and Desktop freshness projections.
- PIT candle/calendar revision, occurrence, quarantine, as-of readers, bounded
  collection stores, and local completeness/finality/DQ gates.
- Supabase RLS, narrow `api` projections and RPCs, Worker-only `worker_api` authority,
  Desktop role/maker-checker/freshness/session guards, and evidence-bound QA reporting.

## Changed

- Replaced the normal process-memory per-stage operations loop with a lease-bound
  durable scheduler lifecycle.
- Converges exact scheduler definitions before claims and performs bounded recovery
  without creating cadence work during convergence.
- Separates safe retry from effectful unknown outcomes. Execution and settlement are
  not automatically retried when their external effect cannot be proven.
- Preserves business failure, warning, retry-wait, and dead-letter state in heartbeat
  evidence instead of reporting scheduler transport success as business health.
- The diagnostic CLI now distinguishes completed, waiting, manual-resolution, and
  failed outcomes with strict exit states.

## Removed

- The legacy `OperationsLoop` and `RunOperationsV2` runtime authority.
- Implicit effect authorization based only on handler identity or a generic binding.

## Safety posture

- `enabled=false`, `mode=paper`, and `live_order_allowed=false` remain hard defaults.
- Render `autoDeployTrigger` and all four boolean Execution V2 flags remain disabled.
- No Toss create/cancel/modify order endpoint is added or called.
- OpenAI output cannot execute orders or promote strategies.
- No hosted credential, actual AAL2 user, external receiver secret, or Production
  provider environment was used for this release.

## Known limitations

- The scheduler does not yet read the current deployment lock and target SHA to stop
  new claims. This is a hard blocker for runtime activation.
- Fixed job priority does not yet provide aging or bounded fairness; sustained
  high-priority load can starve lower-priority due jobs.
- Candle unknown-write resolution, certified dataset replay, official corporate-action
  evidence, and an automatic certified source-to-feature pipeline are incomplete.
- An independent dead-man deployment, durable human ACK/owner/escalation, packaged
  Desktop smoke, signing, and provenance are incomplete.
- The Linux GTK/WebKit dependency path retains one reported `glib 0.18.5` Medium alert.
  It is not dismissed and must be resolved through a compatible parent-stack update.
- Cyber Trusted Access items—hosted Supabase/AAL2, external receivers, actual Toss
  calls, restore, soak, and ten-day Paper/Shadow evidence—are `N/A (external)`, not PASS.

## Rollback

This prerelease does not deploy automatically. Keep the V2 flags disabled. If source
integration must be reversed, use a reviewed forward recovery change from the last
trusted `main` baseline. Applied migrations are forward-only: retain appended schema
objects and disable the dormant runtime instead of rewriting migration history.

No binary asset is attached to this prerelease.
